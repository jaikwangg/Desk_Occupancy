# research/ — บันทึกการค้นคว้า

โฟลเดอร์นี้เก็บ **ผลการค้นคว้าแบบยาว** ที่ยังไม่ได้กลายเป็นการตัดสินใจ
เช่น deep-research report, การสำรวจ dataset, การเทียบ vendor/เซนเซอร์, reference architecture

## แบ่งบทบาทกับ `context.md` ยังไง

| | `context.md` | `research/` |
|---|---|---|
| เก็บอะไร | **ข้อสรุปที่ตัดสินใจแล้ว** + ผลวัดจริงของโปรเจกต์ | **วัตถุดิบ** ที่ยังไม่ตัดสิน — ของคนอื่น, ตัวเลขจากภายนอก, ทางเลือกที่ยังไม่เลือก |
| ใครอ่าน | คนที่จะ deploy / ต่อยอด → อ่านไฟล์เดียวจบ | คนที่กำลังชั่งใจว่าจะเลือกทางไหน |
| ความยาว | กระชับ ตัดของที่ไม่ใช้ทิ้ง | ยาวได้ เก็บ source + ตัวเลขดิบไว้ตรวจย้อน |

**กติกา:** พอ research ชิ้นไหนนำไปสู่การตัดสินใจ → เขียน**ข้อสรุป**ลง `context.md`
พร้อมลิงก์กลับมาที่ไฟล์ต้นทางในนี้ **ห้าม copy เนื้อหายาวไปทั้งก้อน**
(`context.md` เป็น single source of truth ของ "สิ่งที่ตัดสินใจแล้ว" ไม่ใช่คลังข้อมูลดิบ)

## การตั้งชื่อไฟล์

`YYYY-MM-DD-<slug>.md` — วันที่ = วันที่ค้น ไม่ใช่วันที่แก้ล่าสุด
ของที่มีอายุ (ราคา, spec ฮาร์ดแวร์, feature ของ vendor) จะได้รู้ว่าเก่าแค่ไหน

## สิ่งที่ทุกไฟล์ควรมี

- **วันที่ค้น** และ **คำถามตั้งต้น** ที่ใช้ค้น
- **source ที่อ้างได้** (URL) — ข้อไหนไม่มี source ให้เขียนกำกับว่าเป็นการอนุมาน
- **ระดับความเชื่อมั่น** ของข้อสรุปแต่ละข้อ ถ้าเป็นไปได้
- **ท่อนปิด "แล้วยังไงต่อ"** — ข้อไหนเอามาใช้กับโปรเจกต์นี้ได้จริง ข้อไหนใช้ไม่ได้และเพราะอะไร
  (ของที่ **ใช้ไม่ได้** มีค่าพอๆ กับของที่ใช้ได้ — กันไม่ให้เสียเวลาค้นซ้ำรอบหน้า)
